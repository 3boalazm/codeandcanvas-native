# دليل الاستكمال للشات الجديد — Code & Canvas

> **اقرأ هذا الملف أولًا. التكليف التالي تنفيذ استكمال شامل، وليس إعادة التدقيق القديم أو إعلان أن الموقع انتهى.**
> أُعدّ بعد دمج إصلاحات الجولة السابقة في `main`. يكفي مع الملفات المشار إليها لبدء العمل دون الرجوع إلى المحادثة السابقة.

## 0. ملخص فوري — ما الذي يريده المستخدم؟

المستخدم يريد **«تفوير» شامل للموقع**: مراجعة وإعادة بناء التجربة والمحتوى والترتيب والتصميم والوظائف عبر الموقع، بعقلية أعمال وتصميم وتطوير وتسويق، مع استعداد لقبول تغييرات جوهرية ووقت كافٍ. لا يريد مجرد ترقيع عيوب أو تقرير TODO أو تغيير الهيرو وترك بقية الصفحات.

الجولة السابقة أنجزت إصلاحًا واسعًا وتحسينًا حقيقيًا، لكنها **لم تكن إعادة تصميم من الصفر لكل صفحة**، ولم تستكمل الأصول الحقيقية أو الخدمات الخادمية أو قبول الإنتاج. عندما سأل المستخدم «يعني خلاص كدا متأكد انك فورت السايت»، تم توضيح ذلك صراحةً ولم يُدّع اكتمال المشروع.

آخر طلب: **«طيب اعمل ميرج وبعده تقرير تفصيلي للشات الجديد اللي هيفتح بعدك عن اللي المفترض يعمله علشان نكمل بدون الرجوع ليك وبنفس السياق»**.

### الفرق بين الدمج والنشر

- المستخدم ألغى منع الدمج السابق **لهذه الجولة** وطلب الدمج؛ تم تنفيذ ذلك.
- لم تُنفذ أوامر نشر إنتاجي يدوي أو تغيير DNS أو WordPress أو دفع/رسائل حقيقية.
- **يوجد تكامل Vercel آلي:** ظهر فحص ناجح للـPR ثم status ناجح على commit الدمج. لا تقل «لم يحدث أي deployment» بشكل مطلق بعد الدمج؛ قد شغّل الربط الآلي نشرًا.
- لم نتحقق من الدومين الفعلي أو نوع بيئة نشر Vercel أو وظائف الإنتاج. نجاح status ليس قبولًا للإنتاج.
- وثائق التدقيق/التنفيذ القديمة التي تقول «لم يُرفع/يُدمج» تصف وقت إصدارها السابق. هذا القسم يتقدم عليها بشأن حالة Git، ولا يعيد كتابة تاريخ الأدلة.

## 3. ما تم إنجازه — لا تُعد بناءه بالخطأ

### وظائف وعربية

- التحقق يشمل جميع form controls والموافقات وminlength والمطابقة؛ أخطاء موصولة بالحقول، وتركيز أول خطأ، ومنع الإرسال المتزامن.
- إصلاح HTML العربي المزدوج escaping في About/Our Story من المولدات.
- CTAs لتفاصيل الخدمات والباقات المتكاملة تحمل سياق inquiry؛ **23 رمز خدمة** مختبرة: AB-01…06، MA-01…10، HC-01…05، CC-01/02. **لا يوجد CC-03.**
- ترجمة optgroup، تبويبات بلوحة المفاتيح، دلالات FAQ/tabpanel، والحفاظ على query في التحويل المحلي.
- fallback للنماذج عند غياب JavaScript، وPOST بدل GET لتجنب وضع القيم في الروابط إذا فشلت السكربتات.

### الكتب والقارئ والحسابات

- أزيلت محاكاة auth/reset/payment/order/entitlement. Google login معطّل. لا `cc-library` كإثبات ملكية.
- `cc-cart`: قائمة محلية من نسخة واحدة لكل ID معروف. سعر/عنوان/كمية التخزين ليست موثوقة؛ العرض من catalogue مولّد.
- `/account/`: معاينات محفوظة وعدّاد محلي، لا حساب موثق أو مكتبة مشتريات.
- `/checkout/`: **استفسار توفر**، لا شراء. `/thank-you/`: ليس إيصالًا. الأسعار استرشادية.
- القارئ: next/previous دلاليان، مفاتيح RTL حسب اتجاه المحتوى، حدود وتركيز صالحان، H1 لكل قارئ؛ ملاحظات الهاتف/Escape والتخزين تعمل، ولا عمود فارغ عند إغلاقها.
- المعاينات عامة؛ لا fetch لmanifest غير موجود. لا حماية لمحتوى مدفوع منفذة.

### تجربة ومظهر ومحتوى

- هيرو أقصر؛ العمل قبل نبذة الاستوديو والكتالوج؛ إزالة شرائط أرقام مكررة، اختصار About والسير والنهايات، وتقليل أزرار الإغلاق المشتركة.
- مدخل خدمات حسب التحدي وتنقل داخلي للأسعار، وتصحيح تناقض الاشتراكات ورسائل الكتب والخصوصية.
- CSS إضافي للمقاسات والتباين والنماذج والموافقة والقارئ؛ الخطوط العربية وComfortaa محلية OFL، والخطوط الإنجليزية السابقة WOFF2.
- **ثلاثة رسوم نطاق SVG وليست لقطات منتجات**. نُسبت النتائج التقنية المتبقية إلى عرض المؤسس، لا إلى تدقيق مستقل.
- FAQPage + OfferCatalog للخدمات، noindex واستبعاد المسارات التشغيلية من sitemap، وعدم الادعاء بأن الكتب InStock.

### تكاملات واختبارات

- `assets/js/config.js` فارغ افتراضيًا؛ نماذج same-origin `/api/` مع قبول `2xx + accepted:true` فقط، timeout/error وحفظ المدخلات.
- الوضع اليدوي يجهز مسودة لم تُرسل؛ فتح واتساب ليس lead أو حجزًا مؤكدًا.
- قياس اختياري بموافقة وسحبها وDNT/GPC؛ 100 حدث محلي بحد أقصى، بلا form values/query strings/notes. لا purchase وهمي.
- اختبارات Playwright/axe ملتزمة، وفحص isolated generation لـ48 مخرجًا، وبناء لا ينشر أدوات/وثائق/اختبارات.
- خادم المعاينة يمنع الوصول إلى `.git` ومجلدات الأدوات.

## 4. ما لم يكتمل — هذا هو جوهر العمل القادم

**مرور الاختبارات ليس جوابًا عن سؤال المستخدم: هل كل الموقع أُعيد بناؤه إلى المستوى المطلوب؟ الجواب حتى هذا التسليم: لا.**

1. لم تُعد صياغة كل صفحة وتصميمها من الصفر. لا يزال الاتجاه قائمًا على الهوية البحرية الداكنة/التدرجات والزجاج، وقد تحتاج بعض العائلات تغييرًا أعمق لا إعادة استخدام نفس البطاقات.
2. لا يوجد اعتماد بصري/تحريري نهائي لكل الـ42 صفحة؛ الصفحات الطويلة والتكرار الكلي يحتاجان مرورًا مقصودًا.
3. لا صور مشاريع وعلامات ومؤسسين أصلية معتمدة كافية؛ الرسوم الحالية ليست بديلًا عن proof.
4. لا عقود مزودين موصولة فعليًا، ولا خادم حسابات/تجارة/صلاحيات. لا تختزل ذلك في وضع endpoint شكلي.
5. لا `/ar/` mirror أو hreflang أو HTML عربي مستقل قابل للفهرسة.
6. لا اختبار مستخدمين فعلي موثق أو benchmark منافسين جديد؛ التحليل «متعدد التخصصات» السابق ليس لجنة بشرية مستقلة.
7. لا قبول physical devices/Safari/Firefox/screen reader/production Lighthouse/CrUX. axe incomplete لم يُغلق يدويًا.
8. حقوق الخطوط والادعاءات والأرقام والاعتمادات والهاتف والاجتماعيات والقانون وERP تحتاج مالكًا ومصدرًا واعتمادًا.
9. لا cutover مدروس إلى النطاق/WordPress أو خطة رجوع منفذة؛ تحقق مما فعله النشر الآلي قبل أي خطوة مستقبلية.

## 5. خريطة الكود — عدّل المصدر الصحيح

الموقع static HTML/CSS/vanilla JS بلا framework runtime. Node للتشغيل/الاختبارات وPython لتوليد الصفحات. **لا داعي لنقله إلى Next/React لمجرد عمل redesign.** إن رأيت ضرورة معمارية، وثّق السبب والمخاطر أولًا.

## 6. خطة تنفيذ مقترحة بالترتيب — لا تنتظر المالك في كل شيء

### المرحلة A — تثبيت البداية وإعداد قائمة قرارات (أول جلسة)

1. اقرأ المراجع الأساسية وتحقق من branch/status/main وPR #3 دون تغيير الفرع المفروض من الجلسة.
2. شغّل check/build والمعاينة. راجع بيانات الاختبارات واللقطات؛ أعد baseline عند توفر المتصفح قبل تغيير واجهات واسعة.
3. افتح الرئيسية وجميع **عائلات الصفحات** بالعربية والإنجليزية، desktop/mobile؛ لا تكتفِ بصورة أول شاشة.
4. أنشئ ملفًا جديدًا مثل `docs/next-round/PAGE-DECISIONS.md`: route، هدف الزائر، العيب الملحوظ، keep/rewrite/merge/remove، المصدر، CTA المقصود، asset dependency، معيار القبول، ثم حالة التنفيذ.
5. صنّف العمل إلى: يمكن تنفيذه الآن / يحتاج أصلًا أو قرارًا / يحتاج مزودًا أو اختبار إنتاج. لا تحوّل كل المشاكل إلى طلبات مالك.

**مخرج المرحلة:** خطة قرارات قصيرة قابلة للتنفيذ ومعاينة baseline، ثم ابدأ التنفيذ في نفس الجولة إن أمكن؛ ليس تقريرًا مطولًا آخر بلا تغييرات.

### المرحلة B — اتجاه بصري وتحريري شامل (أولوية المرحلة التالية)

**قبول:** صفحات عربية يمكن قراءتها وفهرستها دون JS، روابط تبديل سليمة، annotations متبادلة صحيحة، ومخرجات مولدة قابلة لإعادة الإنتاج. هذه مهمة تنفيذ هندسية، لا يكفي تسجيلها إلى الأبد كبند مؤجل.

### المرحلة F — الخدمات الحقيقية، فقط بعد قرار التشغيل

اتبع `docs/INTEGRATIONS.md` دون اختصار:

- Forms: endpoint server-side، validation/CSRF/rate limiting، durable acceptance، deduplication/idempotency، monitoring، retention/deletion، نجاح وفشل حقيقيان في staging.
- Newsletter: consent/double opt-in إن لزم/unsubscribe؛ request received ≠ subscribed.
- Booking: scheduler حقيقي وconfirmation/webhook؛ click ≠ booking.
- Analytics: collector/لوحات/retention، موافقة وسحبها وDNT/GPC؛ لا GTM يلتف حول الموافقة.
- Commerce: قرار مالك أولًا. إن تقرر: auth sessions آمنة، أسعار وصلاحيات خادمية، signed payment webhooks، refunds، idempotency، محتوى محمي؛ وإلا احتفظ بوضع preview-only المتسق.
- الأسرار في مزود البيئة/الخادم، لا config.js أو Git أو الشات. لا إرسال/دفع حقيقي تلقائيًا للاختبار.

**قبول:** دليل staging فعلي مع redaction مناسب، لا فقط mock `accepted:true`. لا تتوقف المرحلة B/C بسبب عدم اختيار مزود بعد.

## 8. التشغيل وإعادة الاختبار من checkout جديد

```sh
# من جذر المستودع وعلى الفرع المخصص للجلسة الجديدة
git status --short
git branch --show-current
npm ci
npm run check
npm run build

# بعد تعديل مصادر صفحات داخلية:
npm run generate
npm run check

# بيئة عادية بها browser dependencies:
npx playwright install chromium
npm test
```

المعاينة: `npm run dev`، المنفذ الافتراضي3000 وbind هو0.0.0.0. في Agent Mode استخدم أداة العملية الطويلة للسيرفر، لا bash بمهلة. `node dev-server.mjs dist` يعاين build؛ تغييرات build تحتاج إعادة build. لا تترك frontend يستدعي localhost من متصفح المستخدم؛ endpoints نسبية same-origin.

- `npm run test:flows` / `test:matrix` / `test:a11y` للتجزئة.
- `PW_EXECUTABLE_PATH` وJSON `PW_BROWSER_ARGS` لدعم متصفح موجود.
- `TEST_BASE_URL` موجود، لكن helpers تعترض غير localhost/127.0.0.1، وبعض tests وعنوان webServer محليان ثابتان؛ **ليست suite جاهزة لاختبار أي production URL بتغيير متغير فقط**. أنشئ اختبار staging منفصلًا آمنًا عند الحاجة.
- لا تفترض بقاء `node_modules` أو `.cache` أو `/tmp/chromium` أو العمليات في جلسة جديدة.

### إذا منع sandbox تنزيل Chromium الاعتيادي

في الجلسة السابقة استُخدم `@sparticuz/chromium@153.0.0` من npm خارج المستودع، مع استخراج مكتبات NSS/NSPR المضمنة في `bin/al2023.tar.br`. خطوات الاستخراج موثقة في README أدلة التدقيق؛ **خذ إعداد المتصفح فقط، ولا تشغّل harnesses القديمة فوق أدلتها**.

بعد توفير executable والمكتبات، إعداد التشغيل الناجح كان:

```sh
PW_EXECUTABLE_PATH=/tmp/chromium \
PW_BROWSER_ARGS='["--no-sandbox","--no-zygote","--disable-dev-shm-usage","--use-gl=angle","--use-angle=swiftshader","--enable-unsafe-swiftshader"]' \
LD_LIBRARY_PATH=/actual/local/browser-libs/lib \
npm test
```

المسارات أمثلة بيئة وليست ملفات ملتزمة؛ اضبط المسارات الفعلية. **لا تستخدم `--single-process`**: تسبب هنا في إغلاق المتصفح بين contexts وفشل اختبارات بالتناوب. لا تستورد كل flags الخاصة بـSparticuz تلقائيًا ولا تعطل web security بلا ضرورة.

- لا تختلق عملاء/صور/نتائج/شهادات أو تدّع فريق مراجعة بشريًا متعدد التخصصات.
- لا رسائل أو اشتراكات أو مدفوعات حقيقية ضمن QA دون تصريح واضح.

- احترم generator ownership وstable service IDs والروابط القديمة. لا تعالج generated HTML وحده.
- لا تحذف ملفات أو مواد المالك للتخلص من المخاوف؛ وثّق قرارات الحذف والتحويل والحفاظ على المحتوى المفيد.
- خفّض تعقيد CSS بصورة مقصودة؛ لا تضف طبقة overrides فوق كل حالة إلى الأبد. حافظ على اختبارات clipping الفردية، لأن overflow:hidden قد يخفي العيب دون إصلاحه.

## 11. تعريف «خلصنا» للجولة التالية

يلزم تسليم **أربع طبقات منفصلة**، لا كلمة عامة:

1. **تصميم/محتوى:** قرارات لكل عائلة صفحات منفذة ومصورة، تجربة متماسكة وليست هيرو جديدًا فقط، رحلات الزوار الخمسة مفهومة.
2. **هندسة محلية:** generator/build/links/regression محدثة، اللغتان والمقاسات وحالات الخطأ/التركيز/التخزين تعمل، وأدلة الجولة الجديدة محفوظة.
3. **أصول/تحرير واعتماد:** ما تم اعتماده وحقوقه ومصادره، وما بقي يطلب من المالك. لا تعويض الإثبات المفقود بصور متخيلة.
4. **تشغيل/إنتاج:** تكاملات وخدمات حقيقية وQA وحقوق وقانون وإطلاق مثبتة، أو قائمة gates صريحة. لا تدمج اعتماد هذه الطبقة في نجاح الطبقة الثانية.

إذا اكتملت طبقة فقط، قل ذلك بوضوح. التقرير الأخير يجب أن يمكّن أي وكيل تالٍ من معرفة: ماذا يغير، أين مصدره، لماذا، كيف يختبره، وما الذي لا يجوز ادعاء اكتماله.
